# Project-wide decisions

This folder starts with navigation only. Add project-wide decisions here only
when their actual authority and source evidence exist; do not copy TADp's own
development decisions into a new project's history.

Initiative-specific human decisions belong in the owning initiative's
`decision-receipts/` directory. Select the reusable
[decision receipt](../initiatives/decision-receipts/decision-receipt.template.md)
and any required exception fields through the canonical workflow. Templates
provide a record shape, not an answer, approval or historical event.

## Project-owned assumptions and open questions

When an actual project-wide item exists, or no suitable initiative owns it,
select [assumptions-and-open-questions.template.md](assumptions-and-open-questions.template.md)
through the coverage map and instantiate `decisions/assumptions-and-open-questions.md`.
Reuse a suitable existing canonical project register if one already exists.
Do not create an unused register or umbrella initiative. Either numbered review
may discover either item kind independently and may record its own sufficiently
authorized disposition at this proper project destination during the same review.
Definition remains unresolved until that exact disposition has authority.

Record the actual owner/location, origin, scope, dependencies, affected records
and current disposition. The originating initiative links its effect/dependency
without absorbing external work. Verify exact target/current state, governing
revision, branch and sufficient write/decision authority before edits. Missing
authority leaves an owned handoff; separate projects/forks/services retain their
target-naming boundary. Human decisions remain the default, with only specifically
covered delegated methods under recorded authority/exception and actual authorship.

## Actual project decision receipts

Reuse the existing [receipt source](../initiatives/decision-receipts/decision-receipt.template.md)
at `decisions/<receipt-id>.md`, preserving exact human text and authority before
source disposition changes. Use explicit justified non-applicability for fields
that do not apply to a project-owned item. Retain the originating review
separately from the canonical project target, actual responder and resulting-work
authority. Add a row below only for an actual receipt; no sample decision is live.

| Receipt ID | Covered source IDs or event | Canonical source record | Originating review | Disposition | Actual authority or delegated-result author | Event | Commit |
|---|---|---|---|---|---|---|---|

An answer is not initiative acceptance, resulting implementation, protected
architecture revision or reopening of a closed claim. Preserve exact prior
texts/options, receipt history, dormant triggers and independent derived items.
Report pending external dependencies truthfully and block their actual affected
handoff without turning them into unrelated initiative deliverables.
