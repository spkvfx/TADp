# Candidate protocol workspace

This is `C`, the candidate product workspace of the development project
[TADp](../README.md). It is not an installed project, adopted baseline, or Git
repository. It starts with this boundary record only; no feature is seeded.

Place only the sources, tests, and fixtures needed by identified authorized work
here. Declare their pinned provenance and exact destination mapping before
delivery. Keep project decisions, initiative suites, manifests, verification
reports, and completion history in their canonical locations at the project root.
Experiments and candidate replacements do not amend the installed governing suite
or tools. Preserve applicable protection on copied sources.

Use the [development workflow](../docs/development/tadp-development-workflow.md)
and [project instructions](../AGENTS.md). Generic protocol maintenance needs an
explicitly invoked repository-level instruction naming its exact work and this
candidate target, including when the shell is here. Stored project-local prompts
retain [their boundary](../prompts/AGENTS.md).

The serial route is candidate qualification, exact authorized introduction into
`../template/`, development completion, exact authorized promotion into
`../../protocol/template/`, then mapped rollout into `../../protocol/`.
Each boundary needs its own actual evidence and sufficient scoped authority.
Setup performs none of these future operations. Never develop directly in the
upstream distribution.
