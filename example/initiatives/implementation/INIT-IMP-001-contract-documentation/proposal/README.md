## Precedence

1. The Codex invariant suite and the accepted architecture and security suites.
2. Accepted initiative decisions, when later made within that authority.
3. The canonical proposal, realization suite, and realization note as
   non-authoritative intent and context.

A conflict blocks the affected product direction; proposal source never
overrides authoritative evidence.

## Source handling

- Keep the proposal and realization artifacts frozen as historical sources.
- Add a revision rather than overwriting frozen source.
- Record source owner, date, revision, and evidence label.
- Keep credentials, real-person data, exports, and unrelated working files out.
- Link every correction to an assumption or stable `DOC-*` decision.

## Realization handling

The paired suite index supplies identity and one D1 boundary. The realization
note supplies proposal detail only. Neither creates acceptance, resolves its
six questions, or permits another version, initiative, or branch to be
inferred.
