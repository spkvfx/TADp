# Adapting other tools

Git and Codex are the supported project assumptions. Before using another
agent or automation system, assess instruction loading, scaffold boundaries,
evidence handling, exact human gates, source protection, Git safety and
verification reporting against the governing suite.

Record actual compatibility evidence and limitations through the appropriate
project workflow. A product name, prompt invocation or copied instruction file
proves no compatibility. Keep existing authority, lifecycle and output
boundaries. Report unavailable capability rather than claiming a gate passed.

Any required change to generic protocol rules or reusable sources belongs in
separately authorized protocol maintenance, outside ordinary project-local
prompts. Do not disable locks or weaken validation to obtain apparent support.
