# Architecture and authority

The [governing suite](../../evidence/authoritative/LLM/00_Codex_Invariant_Suite_Index.md)
owns the evidence and initiative rules. This guide explains their use; it
cannot change them.

Binding invariants and compatible accepted decisions govern bounded initiative
claims. Proposed work, realization notes, observed implementation and examples
retain their actual standing. Neither installation nor copied wording supplies
human authority.

Keep exact source identity, scope, locator, revision and limitations for each
material claim. The chain is authority, scoped work and decisions, permitted
output, verification, and truthful lifecycle standing. Record a contradiction
instead of weakening a stronger source or rewriting a closed claim.

The project profile records owners and adoption. Initiatives own narrow claims;
their indexes provide navigation, not substitute acceptance. Products identify
actual delivered outputs. A clean baseline supplies none of those live claims.

Use .template.md record shapes from the applicable folder. Other baseline
files copy directly. The protected template library provides reusable details;
it does not become a competing source of substantive protocol authority.
