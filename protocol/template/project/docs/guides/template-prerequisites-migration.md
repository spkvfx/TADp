# Canonical templates and documentary prerequisite recovery

This guide explains the revision owned by
[specification 02](../../evidence/authoritative/LLM/02_Codex_Initiative_Governance_Specification.md#canonical-template-selection-and-use)
and [specification 08](../../evidence/authoritative/LLM/08_Codex_Initiative_Workflow_Specification.md#documentary-prerequisite-preparation).
The [coverage map](../../template/TEMPLATE-COVERAGE.md) locates canonical file,
embedded-section, conditional, and response-shape sources. It adds no record
obligations. Reuse embedded sections instead of creating competing files.

## Adoption

From the adopting project root, inspect Git and preserve unrelated work. Review
the installed sources and their predecessor revision before choosing adoption.
Capture the exact coherent revision commit from its Git history, the actual
human adoption instruction, the current baseline, and affected active work in
the project profile's existing Change record. Use the existing migration ledger
where identity migration is separately needed; this revision does not migrate
identity, accept initiatives, or reopen closed claims.

Install a coherent reviewed distribution and retain the protected source locks.
For a customized installation, reconcile differences through specifically
authorized maintenance and the [integrity guide](protected-source-integrity-migration.md).
Do not refresh a lock to absorb unexplained drift. An active initiative may
retain its earlier compatible governing revision or explicitly migrate through
its change record; do not silently mix stage contracts.

## Using and recovering records

For an identified target and stage, read the stage's Documentary prerequisites
section and apply the shared
[preparation procedure](../../template/prompts/WORKFLOW-CONTRACT.md#documentary-prerequisite-preparation)
before the ordinary entry check. Inventory scoped underlying evidence and
classify each input as current, constructible, stale/incomplete, conditionally
inapplicable with a reason, or blocked. Recover constructible paperwork in
dependency order through its owning stage, satisfying that activity's gates.
Copy the canonical source outside `template/`, retain required sections and
stable identities, replace placeholders, and recompute links at the instance's
actual scope/type depth. Preserve customization and existing valid records.

Each material field needs a precise source locator, standing, revision/event,
and limitations. If exact sufficient human authority exists but its receipt is
missing, capture the actual words and original event, then record the new
capture time separately. This documents an existing decision; it does not
create one. Unsupported fields remain unresolved. Missing immutable identity,
unavailable decisions, failed tests, and incompatible evidence remain blockers.

Validate prepared records and recheck the invoked stage's real gates. A
reconstructed execution record cannot prove unobserved work, and a prepared
acceptance receipt cannot supply absent acceptance. A stale phase-specific
readiness result needs a fresh assessment. A changed accepted claim follows
revision and renewed acceptance; a closed claim requires recorded reopening.

For Stage 9, report preceding preparation changes, capture the file state,
then conduct and verify the assessment without file changes. The readiness
template is a response shape unless another governing rule requires a file.
Report assessment changes separately from whole-invocation changes. A rerun
reuses truthful records and receipts without duplicate decisions or empty
commits. If the canonical source itself is missing, report the governing
requirement and request separately authorized protocol maintenance.

## Verification and limits

From the protocol/adopted root, run the configured interpreter with
`tools/tadp_protect.py check .`, `tools/tadp_validate.py .`, and applicable project-owned verification described in [Validation and quality](../development/validation-and-quality.md).
Protection checks integrity; validation reports objective discrepancies without
creating records. Neither proves semantic evidence completeness or authentic
human authority. Review actual inputs and outputs before relying on a gate.
