# Canonical template coverage and use map

This map selects reusable sources; binding obligations remain in their cited
owning specifications. It does not create additional document obligations.
All required record families inspected for this revision have an existing
canonical source. No new record template was needed: READMEs, embedded sections,
conditional records, and the readiness response shape supply existing coverage.

## Selection and population

Select by role, declared type, governing revision, and stage. Destinations below
are relative to the adopting project root; retain historical paths under their
recorded compatible revision. Angle-bracket components describe an authorized
identity or destination, never permission to infer it. Copy a file outside
`template/`, populate the instance, replace placeholders, preserve stable IDs,
and recompute relative links from its actual directory depth. Embedded sections
stay inside their owning record. The ordinary Stage 9 result is a response
shape; a durable instance requires another explicit governing requirement.

Use all material scoped evidence, following precise references to the underlying
sources. Start with applicable invariants and accepted decisions, then inspect
source inventories, realization inputs, actual human instructions and receipts,
initiative/dependency/product records, implementation, configuration, tests,
verification, and Git history. Include proposed and partial effort without
promoting it. Preserve each material claim's path or stable ID, precise locator,
standing, revision/date, and limitations. Record unavailable, stale, conflicting,
and out-of-scope sources. Leave unsupported fields explicitly unresolved.
Neither plausible prose nor placeholders satisfy an entry gate.

For every instance, retain its purpose, trigger, owner, required sections,
inputs, source standing, evidence links, unresolved fields, justified
non-applicability, verification and next consuming activity through the source's
existing fields and the metadata here. Reuse valid records; do not duplicate
customized sources. Prepare missing documentary prerequisites only under the
[shared procedure](prompts/WORKFLOW-CONTRACT.md#documentary-prerequisite-preparation)
and the owning activity's actual entry gates. Missing authority, immutable
identity, actual work, or passing verification cannot be manufactured.
Capture sufficient existing human words before reliance without asking for the
same decision again; preserve original event and capture time separately.
Missing canonical sources require separately authorized protocol maintenance.

## Coverage inventory

The following is a reference inventory, not an action list. A row marked
`covered` means its reusable shape exists; it makes no adoption, acceptance,
readiness, completion or release claim about a live project. Conditional
records are created only after their actual trigger. A section row never
creates a second independent record. The initial suite's `members` identify
its constituent sources; Stage 3 excludes late decision/delivery/completion
records. Historical or optional custom outputs remain scoped by the accepted
work and do not add universal obligations.
