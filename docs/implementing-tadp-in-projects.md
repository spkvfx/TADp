# Implementing TADp in projects

Use the portable [getting-started guide](../protocol/docs/development/getting-started.md)
for the complete installation and adoption procedure. It owns component copying,
project/Git roots, hooks, initial checks and the first initiative. This page is
an entry point, not a second installer.

Implementation means installing the scaffold, recording explicit prospective
adoption, integrating ownership and checks with project practices, then
operating the [initiative workflow](../protocol/docs/development/initiative-workflow.md).
Git and Codex are required; Python 3 runs bundled validation. Start with a
narrow pilot before migrating existing work. Copying and structural checks
create no human decision, acceptance, completion or release.

The current distributed guide still includes some reference-maintainer
material. Its expanded portable replacement is prepared under
`TADp/protocol/documentation/` and awaits the controlled delivery route recorded
in the [preparation map](../TADp/evidence/non-authoritative/documentation-split/preparation.md).
Use the [contributor guide](developing-tadp.md) for this repository's maintenance.
