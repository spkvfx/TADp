# Adopting positional prompt keywords

The authoritative contract is
[specification 11](../../evidence/authoritative/LLM/11_Codex_Prompt_Keyword_Specification.md).
It applies when interpreting every TADp task, including ordinary analysis and
requests. The specification owns the vocabulary, defaults, positional rules,
action-list scheduling, exception requirements, and extension process.

## Adoption

Capture the current Git baseline, governing revision, protected locks, active
work, and historical claims before adoption. Obtain specific authority to
install this invariant and reusable-source revision. Compare the complete
source and consumers against the authorized distribution, reconcile local
instructions without expanding their targets, run tests and validation, then
refresh only specifically authorized locks. Record the actual delivery commit
and the adoption event. Reading or copying the registry activates no example.

Copy the specification and index, affected suite consumers, universal root
and reusable-project instructions, shared and numbered workflow prompts,
project-local prompt guidance, receipt sources, shared tool, validator, tests,
and documentation as one compatible distribution. Do not install a partial
consumer set or maintain a competing keyword allowlist. The universal project
entry point must resolve to the installed specification.

Existing initiatives retain their recorded revision until explicitly migrated.
Record the selected revision and scope before applying the new contract to
resumed work. Preserve source prompt and block identity, prior settings,
decisions, evidence, failures, and receipts; do not rescan historical prompts
and retroactively apply a keyword or scheduling rule. This adoption creates
no initiative exception and settles no open question. Closed claims and
substantive successors retain their existing governed workflow.

## Operating and extending

Record effective settings by source block before dispatching work. Distinguish
requested gate modes from authority to except an actual rule; preserve each
gate and governing revision in an exception record before relying on it.
The LLM may author the paperwork from sufficient explicit authority. It must
obtain confirmation for an inferred directive or exception. Restoring a gate
does not validate earlier skipped checks. A prompt-work result with waived
prerequisites is reported separately from ordinary lifecycle qualification.

For a new keyword, give the exact name and behavior in an explicit instruction.
The LLM prepares the canonical entry and consumer reconciliation using
specification 11's **Adding a keyword** format. Review inferred scope or
exceptions before adoption; registration is a protected invariant revision.
An unknown operative spelling stays inactive and is reported. The registry
does not supply unavailable tool capabilities or external-action authority.

## Verification and limits

Run the protected-source check, full validator, and regression suite using
the configured interpreter. Inspect mirror parity and actual authority and
reconciliation, rather than relying on structural checks to certify them.
The shared keyword helper validates declared inputs and scheduling; it does
not intercept tools, authenticate humans, or infer which prose is operative.
Agent consumers must apply preview, local-only access, independent review,
and exception requirements to their real actions. Report unavailable review
or concurrency capacity truthfully.
