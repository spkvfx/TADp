# Legacy initiative decomposition guide

Use this guide when an existing initiative combines outcomes that now violate
the narrow-scope rule. Decomposition is a governed revision, not a folder
cleanup.

## Procedure

1. Freeze the historical record. Capture the initiative ID, current lifecycle
   state, accepted or completed claim, branch and commits, products, and
   governing sources. Do not rewrite earlier truthful records.
2. Identify each independent outcome using the mandatory split triggers in the
   authoritative initiative scope specification.
3. Build a complete ownership map. Assign every requirement, assumption,
   question, decision, source, invariant mapping, dependency, product,
   verification gate, risk, and deferred item to one continuing owner.
4. Choose siblings unless a genuine parent specification owns a bounded claim
   that the smaller work depends on. Do not invent a parent merely to preserve
   the old directory shape.
5. Obtain explicit human authority for the decomposition and record a decision
   receipt. State whether the legacy initiative continues, is superseded, is
   cancelled, or is reopened for narrowing.
6. Create each new initiative through the normal preparation and creation
   workflow with a recorded dedicated child or shared scope execution assignment. Give it its own scope assessment, lifecycle,
   decisions, acceptance claim, and verification.
7. Add durable predecessor, successor, parent, and sibling links. Preserve
   source IDs; when an item moves, record its old ID and new owning record rather
   than silently renumbering history.
8. Reconcile shared status, dependencies, products, and completion claims. No
   requirement may disappear, be counted twice, or remain without an owner.

## Required decomposition record

Keep a mapping with these fields in the revised legacy initiative:

| Legacy item | Prior claim or owner | New initiative and item | Relationship | Effective event | Decision receipt | Verification impact |
|---|---|---|---|---|---|---|

The mapping is complete only when every material legacy item has exactly one
current disposition.
